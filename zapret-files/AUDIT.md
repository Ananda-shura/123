# Аудит Zapret 1.10.4 для Windows 11

Дата отчёта: 24 октября 2026 года. Исследована предоставленная копия; доступа к компьютеру пользователя и его провайдеру нет. Это статический аудит и подготовка проверяемого кандидата конфигурации. Воспроизведение YouTube, скорость Steam, пинг/джиттер/потери CS2 и запуск после перезагрузки Windows здесь **не проверены**.

## Результат и границы установленных причин

Архив содержит оригинальные файлы официального релиза, без выявленных подмен. Найден конкретный пробел области обработки YouTube: список `list-google.txt` применяется к TCP 443, но не включён в QUIC-hostlist. При исходном IPSet `none` соединения к YouTube по UDP 443 могут остаться без требуемой десинхронизации. Наличие этого пробела в файлах подтверждено; его роль в наблюдаемых сбоях на компьютере пользователя остаётся гипотезой.

Причина задержек Steam не установлена по архиву. Для обычного `general.bat` широкая обработка игровых портов текущими настройками не подтверждена. Для ALT5 найдена широкая обработка IPv4 TCP независимо от Game/IPSet; для EXP — более широкое UDP-правило на отдельных портах. Неизвестно, какой BAT или какая командная строка службы реально применяются на Windows.

Подготовлен отдельный минимальный профиль YouTube для TCP/UDP 443. Он оставляет базовую TCP-стратегию `general.bat`, исправляет охват QUIC, не использует Game/IPSet и не вызывает `service.bat`. Исходные файлы сохранены. Такой профиль не предназначен для обхода Discord и других сервисов из общего списка. Полнота работы YouTube и отсутствие ухудшений Steam требуют контролируемой проверки на целевом компьютере.

Всего 22 стартовых `general*.bat`. Все ссылки этих BAT на бинарные файлы и исходные списки существуют. `*-user.txt` отсутствуют в архиве намеренно: `service.bat :load_user_lists` создаёт их при первом запуске. Отсутствие такого файла до первого запуска не доказывает поломку релиза.

Повторы содержимого `ACTIVE_GAME_UDP.bin` = `quic_initial_4pda_to.bin` и `ACTIVE_DISCORD_UDP.bin` = `quic_initial_steamcommunity_com.bin` соответствуют выбранным активным шаблонам, а не лишним повреждённым компонентам. Имена `steam*` в шаблонах fake не означают, что правило применяется к Steam: область задают фильтры, а шаблон — содержимое поддельного пакета.

Зависимости запуска: `general*.bat` → вызовы `service.bat` → загрузка настроек/создание user-списков → `winws.exe` → DLL/WinDivert64.sys + списки/шаблоны. Менеджер службы извлекает параметры из BAT и записывает отдельную командную строку службы. Изменение файла списка может повлиять при загрузке/перечитывании; изменение BAT не переписывает уже зарегистрированную командную строку службы автоматически.

## Подтверждённые особенности и риски сценариев

| Место | Наблюдение по файлам | Практическое следствие |
|---|---|---|
| `general*.bat`, начало | Вызов `service.bat status_zapret` вызывает `:tcp_enable` | Обычный запуск может выполнить глобальный `netsh interface tcp set global timestamps=enabled`; новый профиль этого не делает |
| `service.bat :test_service` | При уже работающей службе выводится предупреждение и `pause`; возврат идёт в вызывающий BAT | Это не надёжный запрет второго экземпляра; `general*.bat` продолжают исполнение |
| `general*.bat` | `cd /d %BIN%` без кавычек, далее `start` без проверки успешного старта | Устойчивость путей с особыми символами и видимость ошибки недостаточны; пробелы сами по себе не доказывают отказ `cd`, поскольку `cd` имеет особую обработку |
| `service.bat` | Смешаны кодовые страницы 65001/437, английские строковые проверки вывода команд | На иной локализации часть статусов может определяться неверно; проверка на Windows не выполнена |
| `service.bat :service_diagnostics` | Может менять timestamps, удалять WinDivert и GoodbyeDPI в ветке устранения конфликта, предлагать очистку Discord | Это не исключительно чтение состояния; для первичного сбора подготовлен отдельный сценарий без таких изменений |
| `service.bat :service_remove` | Удаляет службы и принудительно завершает `winws.exe` по имени | Может затронуть другую установку; не применять как автоматический откат новой конфигурации |
| `service.bat :service_install` | Создаёт постоянную автослужбу и меняет timestamps | Требует отдельного согласования пользователя; в облаке не выполнялось |
| `service.bat` обновление IPSet | Загрузка актуальных данных из `main`, включая curl-ветки с ослаблением revocation-проверок | Не является фиксированной конфигурацией 1.10.4; новый профиль не загружает обновления и не меняет настройки доверия |
| `utils/test zapret.ps1` | Может временно включать IPSet `any`, запускать стратегии, завершать все `winws` | Не является пассивной диагностикой; аварийное прекращение создаёт риск остаточного локального состояния, несмотря на штатное восстановление |
| `utils/test zapret.ps1` | Есть проверка наличия процесса вместо функциональной готовности, HTTP- и ping-проверки | Наличие PID и успех веб-запроса не доказывают воспроизведение видео либо отсутствие ухудшения CS2 |

Подозрительных внешних бинарных загрузок в путях запуска не установлено. Проверка версии обращается к официальному `raw.githubusercontent.com`; обновления IPSet/hosts тоже берутся из официального репозитория. Запрос DPI-checkers идёт к `hyperion-cs.github.io` и расширяет сетевые зависимости штатного теста. Наличие доверенного источника не отменяет необходимости прочитать действие команды перед административным запуском.

## Область сетевой обработки

В обычном `general.bat` WinDivert захватывает TCP 80,443,2053,2083,2087,2096,8443 и дополнительный GameFilterTCP; UDP 443,19294–19344,50000–50100 и GameFilterUDP. Захват драйвером и применение `dpi-desync` — разные этапы: пакет может пройти через драйвер, но не совпасть с hostlist и не получить десинхронизацию.

`Game Filter` выключен: файла `utils/game_filter.enabled` нет, `:game_switch_status` выставляет TCP/UDP `12` вместо широкого диапазона 1024–65535. Это формальная портовая заглушка, не полноценное исключение игрового процесса. `IPSet Filter` — `none`: `ipset-all.txt` содержит `203.0.113.113/32`, адрес документационного диапазона. Большой `.backup` не применяется, пока не восстановлен в активный список. Это штатные настройки архива, они полностью совпадают с официальным релизом.

Правила обычного `general.bat` идут по порядку: общий QUIC → Discord/STUN UDP → Discord.media TCP → Google TCP → общий HTTP/HTTPS → IPSet QUIC → IPSet TCP → игровой TCP → игровой UDP. Область первого подходящего профиля важнее наличия похожего правила ниже. Google TCP не наследует доменные/IP-исключения общего профиля; это не доказывает конфликт без совпадающего домена/IP.

### YouTube

`youtube.com`, `googlevideo.com`, `ytimg.com` и связанные API/картинки входят в `list-google.txt`. Пересечение с `list-general.txt` пустое. Во всех 22 стартовых сценариях нет QUIC-правила с этим Google hostlist. В обычном `general.bat` общий QUIC-hostlist не совпадёт с указанными доменами, а IPSet-заглушка не подхватит их обычные адреса. Поэтому наличие `--wf-udp=443` само по себе не решает обход YouTube по HTTP/3.

Это условный вывод для распознаваемых Initial с именем YouTube и штатных списков; фактическое использование QUIC, браузерный DoH/ECH, IPv4/IPv6, CDN и возможная другая командная строка службы неизвестны. Отключение QUIC глобально не выполнялось. Новый профиль добавляет явное соответствие YouTube для UDP 443 наряду с TCP 443.

### Steam и игры

В общем hostlist нет явных доменов Steam/Valve. В исключениях уже есть `steampowered.com`, `steamcommunity.com`, `steamusercontent.com`. Это не полный список всей инфраструктуры Steam и не защита произвольного игрового UDP: доменное исключение требует доступного имени на уровне протокола. Автоматическое добавление всех адресов Steam в IP-исключения не выполнялось; CDN может быть общим с другими сервисами.

Для обычного профиля при текущем Game `disabled`/IPSet `none` широкая десинхронизация Steam не доказана. **ALT5** обрабатывает широкий IPv4 TCP без hostlist и без доменных исключений; Steam HTTPS может попасть в него. **EXP** обрабатывает `unknown` UDP на 19294–19344,50000–50100 с `any-protocol=1`; игровой поток на таких портах может совпасть. Полный разбор стратегий — `STRATEGIES.md`.

Новый профиль не содержит игровых диапазонов, IPSet, Discord/STUN и catch-all DPI-правил. Steam не входит в его список десинхронизации. При этом трафик других приложений на TCP/UDP 443 всё ещё может проходить через WinDivert; нулевой накладной расход и отсутствие конфликтов с античитом не гарантируются. Пинг ICMP до сервера не заменяет измерение игрового RTT и потерь внутри CS2.

## Гипотезы и проверки на компьютере пользователя

| Гипотеза | Как проверить | Что будет доказано |
|---|---|---|
| YouTube ломается на необработанном QUIC | Один браузер/ролик/качество; сравнить исходный и новый профиль; в DevTools проверить h3 против h2 | Улучшение вместе с фактом h3 поддержит гипотезу; один успешный curl её не подтверждает |
| DNS возвращает недоступный адрес | Сохранить результат DNS и браузерный режим DoH без изменения настроек; сравнить ошибки DNS/TLS | Отделение отказа разрешения имени от отказа TLS/видео |
| Нужен иной TCP multisplit | Сравнить исходный базовый TCP и альтернативу при одинаковом h2, не меняя одновременно DNS | Пригодность стратегии для конкретного маршрута, не универсальность |
| Служба запускает не тот BAT | Снять имя службы, путь и фактические аргументы `winws.exe`; сопоставить с файлом | Какая стратегия реально активна; изменение BAT само по себе это не устанавливает |
| Несколько фильтров/процессов конфликтуют | Прочитать процессы/службы, проверить BFE и наличие других фильтров; ничего не удалять автоматически | Наличие потенциального конфликта, не его причинность без A/B |
| Steam затрагивается ALT5/EXP или новым IPSet | Проверить реальные аргументы, активный список и порты проблемного соединения | Совпадение с правилом; эффект на скорость/RTT требует измерения |
| Проблема браузера/расширения | Отдельный чистый профиль без изменения системных параметров, тот же ролик | Влияние профиля браузера; не необходимость отключать защиту Windows |
| Замедление вне Zapret | Повторить одинаковый тест без Zapret, исходный, новый, затем снова без Zapret | Устойчивость эффекта и влияние времени/маршрута |

Для каждой из трёх конфигураций: YouTube 1080p не менее 10 минут, перемотка и изображения, данные «Статистика для сисадминов»; Steam магазин/сообщество/библиотека и одинаковая загрузка; CS2 один сервер и одинаковая продолжительность с игровым RTT, джиттером и потерями. Повторить минимум три прогона. Не заполнять отсутствующие измерения нулями. HTTP-ошибка 403 на корне CDN сама по себе не доказывает сетевую недоступность.

## Изменения и оставшиеся ограничения

Добавлен отдельный кандидат конфигурации и инструменты диагностики; исходные BAT, списки, бинарные компоненты и драйвер сохранены. Рабочую Windows-конфигурацию здесь не меняли. Автозапуск не создавали. Установка службы/задачи и изменение системного DNS, Defender, брандмауэра или сетевого стека не выполнялись.

Минимальный профиль исправляет обнаруженный пробел охвата и уменьшает область десинхронизации. Выбор конкретных значений TCP и QUIC остаётся исходным испытательным вариантом. Проверки синтаксиса/целостности и результат сравнений архива относятся к подготовленным файлам; они не подтверждают работу драйвера, успешный TLS к провайдеру или стабильность видео.

Откат: остановить только запущенный новый экземпляр через его окно и вернуться к сохранённой исходной папке. Поскольку исходные файлы не перезаписываются, не требуется автоматически удалять службы или восстанавливать глобальные сетевые настройки. Подробные действия — `README-INSTALL.md`.

пустой файл; пустой IPSet означает any. Новый профиль не использует этот updater/IPSet.
